# 当前使用方法与系统流程

本文描述正式版 **Doubao Murmur v1.3.1（控制端build20、Mirror build19）**。应用身份为 `com.doubao.murmur`，显示名和可执行文件均为 `Doubao Murmur`。发布说明见[release-notes.md](release-notes.md)。

## 使用方式

1. 把光标放到目标输入框，按 `Control + /` 开始。
2. 应用确认热键释放、临时输入框聚焦和豆包输入源就绪，然后合成右 Command 启动语音输入。
3. 说完后按一次物理右 Command 停止。录音或停止等待中的 `Control + /` 均被忽略，不会因此丢弃文字。
4. 应用观察到本会话的下划线提交、物理停止键抬起，并在下一主循环重新验证焦点、当前无下划线及文字修订号后，自动执行录音开始时捕获的路由。
5. `ESC` 主动取消并丢弃当前录音，不影响以前保留的文字。

停止后 1.5 秒仍未提交，只显示“仍在等待输入法提交”；不会因此丢弃内容。15 秒仍未满足完成条件则停止自动粘贴，并将已经观察到的文字保留为可恢复草稿。成功路径不需要等待满1.5秒或15秒。

未观察到下划线提交时，不把“文本非空”或“文本不再变化”当成完成。再次出现下划线会撤销旧的锁文授权；迟到事件和旧会话回调不能触发新的粘贴。

## 输入框位置

菜单栏 → “输入框位置”：

- **跟随鼠标坐标（默认）**：开始录音时读取控制端鼠标位置，正常在鼠标正上方显示，底边左起1/3对齐鼠标。上方放不下则改到下方；右侧不足向左调整，左侧不足向右调整，保留屏幕可用区边距。
- **屏幕上方**：在开始录音时鼠标所在屏幕顶部居中显示。

选择自动保存，重启仍有效，下次开启输入框生效。一轮录音中的位置固定，不追随鼠标；等待提示、存储失败扩展框和延迟发送失败提示沿用各自会话的位置。显示器断开或布局变化时重新限位。

“跟随鼠标坐标”依赖控制端鼠标，不读取被控端输入光标。请先把鼠标移到目标输入框附近，再按Control+/。系统辅助功能放大开启时，输入框确认获得焦点后向系统报告一次位置；不修改缩放倍率或设置。屏幕可用区不等于缩放后视野，用户已验收本版基本使用；不同倍率及多屏组合仍需在具体设备上确认。

## 最近文字与恢复

菜单栏数量表示尚未查看的新失败提醒。打开“最近文字与恢复”即清除当时已有的提醒数字；记录和失败状态仍保留，新失败重新计数。窗口可查看完整文字、复制或明确删除。失败提示与录音浮窗共用会话定位规则，正常420宽、16圆角材质；提供“查看记录”和关闭按钮，不自动抢焦点。录音中暂缓显示最新提示，空闲后展示8秒；关闭提示不会清除菜单未读数量，打开记录才会清除。

- 原文加密暂存磁盘，最多保留3天；密钥只在本次进程中，退出/崩溃/重启后不恢复。正常退出删除本次目录，下次启动清理已失去所有者的残留密文。
- 历史索引只留少量状态和时间。打开窗口时按需加载文字，关闭释放；当前录音、复制和系统文件缓存仍需少量内存，不能保证零内存。
- 最近20条包含成功投递、失败、未知及等待回执的会话；活动会话也预留一个位置。
- 3天以内，只有已投递记录可按最旧顺序自动淘汰。失败和待回执记录不会被新录音覆盖；全部20个位置不可淘汰时，先复制或删除已有记录再开始新录音。
- 过期记录在读取、新会话、打开窗口及定时检查时删除；电脑休眠期间需等待唤醒。删除失败时立即停止展示和读取，并重试清理残留文件。
- 复制和关闭窗口不会删除记录；复制失败仍保留原文。
- “尚未确认完成”表示输入法未完成确认，使用前应自行核对。
- “结果未知”表示无法确认回执，先检查目标输入框，避免重复。应用不会自动重试，也没有一键重发。
- “已投递按键”不代表目标输入框已经插入文字；近期这类文字也保留在恢复列表。
- 异常恢复不自动改写剪贴板；正常粘贴流程仍按所选模式操作剪贴板。
- 临时记录写入失败时保留当前输入框并停止自动投递，显示“复制当前文字”；复制成功后关闭。ESC仍表示主动丢弃。读取失败可重试或删除，不能宣称已复制。

## 三种粘贴路由

| 模式 | 行为 |
| --- | --- |
| 本机 | 恢复原目标，写入本机剪贴板并投递 Command-V；失败保留草稿。 |
| UU兼容 | 先预发布文字供UU同步，恢复目标后监测本机剪贴板稳定，再投递Command-V。 |
| UU快速 | 使用现有helper HTTP v2，经UU loopback映射请求远端写剪贴板并投递Command-V。 |

菜单中的“剪贴板稳定时间”只影响兼容模式；快速模式下禁用该控件。新录音会取消上一笔尚未执行的本机/兼容粘贴并保留文字，不取消已经发送的快速模式请求。

helper安装、权限和端口映射按[安装说明](../packaging/murmur-mirror/README.md)。Mirror build19采用 `preflight-snapshot-v2`：在发送前准备整个按键对，避免发送Command-V后再读取已受合成事件影响的HID状态并污染抬键。控制端build20包含同一共享修正。本轮位置功能只需更新控制端，Mirror保持build19；HTTP v2和两端 `127.0.0.1:17771` 配置不变。用户已确认Command/Delete基础场景，其他并发时序与多目标场景仍需实测。

## 状态与诊断

```text
preparing -> recording -> stopping
                         | 1.5秒：等待提示，继续观察
                         | 完成条件成立：修订号核验 -> 冻结 -> 路由投递
                         | 15秒/失焦/手势打断：保存草稿 -> 恢复原目标
投递结果 -> 已投递按键 / 明确未发送 / 结果未知 -> 最近文字与恢复
```

控制端事件库：`~/Library/Application Support/Doubao Murmur/paste-orders-controller.sqlite3`。

新事件统一使用 `session.` 前缀，覆盖所有路由；快速模式原有订单事件保持兼容。用 request_id 关联快照、停止、锁文和投递。`details_json` 只含修订号、marked状态、字数、路由、阶段、原因和应用版本；表内继续保存UTC与单调时间。不会保存识别原文、原文hash或窗口标题。

关键事件：`session.physical_right_command_stop_down/up`、`session.marked_text_unmarked`、`session.commit_soft_deadline`、`session.commit_wait_failed`、`session.final_text_locked`、`session.paste_not_sent`、`session.paste_result_unknown`、`session.paste_event_posted`。停止键down被输入法吞掉时会记录 `session.physical_right_command_stop_up_without_down`。

超时原因区分 `missing_key_up`、`missing_marked_text`、`commit_pending`。日志不含原文，因此不能单靠日志证明最终文字完全一致。

## 开发验证与边界

无App启动、无真实按键或剪贴板操作的逻辑/协议测试：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
```

正式应用构建：

```bash
xcodegen generate
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project doubao-murmur.xcodeproj -scheme doubao-murmur \
  -configuration Release -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath build CODE_SIGN_IDENTITY=- build
```

真实两机验收尚需：快速模式10/30/100/300字各5轮；本机和兼容模式各30/100字各3轮。以对端实际内容为准，记录停止、提交、锁文和文字出现的时间，并检查断连、慢提交、权限及连续会话。上述为进一步的覆盖矩阵，不代表用户逐项完成；本版已由用户确认作为正式版。

首期保留的边界：helper 未认证、远端目标未绑定、并发请求未保证执行顺序、ACK不证明目标消费。认证、目标绑定、有序交付仍属后续范围，不能描述为已经解决。更新链路的校验和回退机制见下节。

## 更新与验收边界

内置更新只接受同发布者签名、同应用身份、正式渠道及预期更高版本。下载限200MiB，ZIP路径/类型/实际解压内容限500MiB校验完成后才解包；同卷暂存、原子交换保留旧包，使用匹配版本/PID/随机nonce的启动回执判断就绪，启动失败停止新进程后回退。旧包位于应用同目录的 `.murmur-update-<UUID>/`，不会先删除旧App。若新进程无法正常停止或目标已被外部替换，则保留备份并停止自动回退。

当前正式安装包使用ad-hoc签名，不能验证发布者，因此**自动安装被禁用并明确提示手动更新**。签名/版本策略、实际文件交换与失败回退已有自动验证；正式证书签名、在线下载和真实GUI启动失败回退仍未做端到端验收。

后续设备验收需覆盖Delete、空格、A、左右Command、连续长文、断连和失败UI。Mirror提供版本/策略字段与60秒显式诊断入口，默认不常驻按键监听。
